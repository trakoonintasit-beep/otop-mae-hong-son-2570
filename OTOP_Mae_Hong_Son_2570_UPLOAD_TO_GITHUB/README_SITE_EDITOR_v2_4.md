## วิธีติดตั้ง (สำหรับเว็บไซต์ที่เปิดใช้งานแล้ว)

### 1. สำรองข้อมูลและอัปโหลดไฟล์

เข้า GitHub Codespaces ของ Repository ปัจจุบัน แล้วเปิด Terminal ที่ root ของ Repository:

```bash
git switch main
git pull --ff-only origin main
# สำรอง/สร้างสาขาก่อนปรับจริง
# git switch -c website-editor-v2-4
```

อัปโหลดไฟล์ `OTOP_Mae_Hong_Son_2570_Website_Editor_v2_4.zip` ไปที่โฟลเดอร์ root ของ Codespaces แล้วแตกไฟล์ลงโฟลเดอร์หลัก:

```bash
unzip -o OTOP_Mae_Hong_Son_2570_Website_Editor_v2_4.zip -d .
```

ต้องมี `index.html` และ `admin.html` ใน **root** ของ Repository ไม่ใช่โฟลเดอร์ ZIP ชั้นนอก จากนั้นตรวจการเปลี่ยนแปลง:

```bash
git status --short
git add index.html admin.html assets/admin.js assets/site-settings.js \
  assets/site-settings-admin.js assets/site-customization.css assets/site-editor.css \
  supabase/migrations/20261020_site_editor.sql README_SITE_EDITOR_v2_4.md
git commit -m "Add master admin website content and cover editor"
git push origin main
```

รอ GitHub Actions → Pages deployment สถานะ `success` แล้วรีเฟรชหน้าเว็บไซต์

### 2. ติดตั้งตาราง Site Settings บน Supabase

1. เปิด Dashboard โปรเจกต์ OTOP ที่ตั้งใน `assets/config.js`
2. เมนู **SQL Editor** → **New query**
3. เปิดไฟล์ `supabase/migrations/20261020_site_editor.sql` คัดลอกโค้ดทั้งหมด → Run
4. หากยังไม่ได้ติดตั้งระบบสิทธิ์ Admin หลัก/รอง ต้องติดตั้ง `20261019_admin_roles.sql` ก่อน เพราะ SQL นี้ใช้ `public.is_otop_master_admin()`
5. เมื่อ SQL สำเร็จ ตาราง `public.otop_site_settings` ต้องมีหนึ่งแถว `id=1` และ `content={}`

**ไม่ต้องรัน `setup.sql` เดิมซ้ำ** ไม่ต้องใส่ service role key ใน GitHub และไม่ต้องสร้าง Edge Function ใหม่สำหรับเมนูนี้

### 3. เริ่มแก้เนื้อหา

1. เปิด `.../admin.html` และเข้าสู่ระบบด้วย **Admin หลัก**
2. เลือกแท็บ **🎨 จัดการหน้าเว็บไซต์**
3. เปิดแต่ละหมวดและแก้ข้อความ/เลือกภาพจากเครื่อง
4. เปลี่ยนตำแหน่งหัวเรื่องและปรับขนาด ข้อความในหน้าตัวอย่างจะเปลี่ยนทันที
5. เลือก **คอมพิวเตอร์ / มือถือ** เพื่อตรวจทั้งสองแบบ
6. กด **บันทึกและเผยแพร่เว็บไซต์** → **ยืนยัน**
7. เปิดเว็บไซต์สาธารณะอีกแท็บ รีเฟรชเพื่อตรวจค่าที่บันทึก

### รูปภาพหน้าปก

- รองรับ JPEG, PNG, WebP ขนาดไม่เกิน 5 MB; แนะนำภาพแนวนอน 1600×900 พิกเซลหรือมากกว่า
- หากเลือกไฟล์จากเครื่อง ระบบแสดงภาพตัวอย่างก่อนบันทึก และอัปโหลดเข้า **Supabase Storage → `product-images` → `website/`** เมื่อกดเผยแพร่
- ถ้าระบบแจ้ง Storage policy denied ให้ตรวจ `supabase/setup.sql` (Bucket ต้องชื่อ `product-images` และสิทธิ์อัปโหลดต้องอนุญาต Admin)
- อัปโหลดรูปสำเร็จแล้วไม่ลบไฟล์เดิมให้อัตโนมัติ เพื่อหลีกเลี่ยงการลบรูปที่กำลังใช้งานอยู่ สามารถจัดการไฟล์เก่าจาก Storage Dashboard ภายหลัง

### การรักษาสิทธิ์และความปลอดภัย

- แสดงฟอร์มสำหรับ Admin หลักเท่านั้น และ SQL ใช้ **Row Level Security** อนุญาตให้แก้ไขจาก `public.is_otop_master_admin()` เท่านั้น
- Admin รองไม่เห็นแท็บนี้และไม่สามารถ UPDATE ตารางได้ แม้เรียก API เอง
- บุคคลทั่วไปอ่านได้เฉพาะเนื้อหาหน้าเว็บที่เผยแพร่ ไม่สามารถเขียนข้อมูล
- ข้อความที่แก้ไขแสดงด้วย `textContent` (ไม่ใช่ HTML) และภาพจำกัดชนิดไฟล์/URL
- ห้ามกรอกรหัสผ่าน ข้อมูลบุคคลที่ไม่ควรเผยแพร่ หรือข้อมูลภายในลงในฟอร์มตั้งค่าหน้าเว็บ

### การย้อนคืน / แก้ปัญหา

- **ไม่พบเมนู:** ออกจากระบบและเข้าใหม่ด้วย Admin หลัก ตรวจ GitHub Pages deploy และบังคับรีเฟรช `Ctrl+F5`
- **เห็นเมนูแต่บันทึกไม่ได้:** รัน SQL migration แล้ว? ตรวจสิทธิ์ `master_admin`, `is_active=true` และ URL Supabase เดิม
- **ภาพไม่ขึ้น:** ตรวจชนิดไฟล์, จำกัด 5 MB, สิทธิ์ Storage, หรือลิงก์ `https://...`
- **ข้อความไม่อัปเดต:** รีเฟรชหน้าเว็บไซต์ และตรวจ `otop_site_settings.content` ใน Table Editor
- **แก้ไขทับกัน:** หากมีคนอื่นบันทึกก่อน ระบบจะแจ้งให้โหลดค่าที่เผยแพร่ใหม่ เพื่อป้องกันการทับค่าแบบไม่ตั้งใจ
- **คืนค่าต้นแบบ:** เมนู `คืนค่าข้อความต้นแบบในหน้าตัวอย่าง` จะไม่เปลี่ยนเว็บไซต์ จนกดบันทึกยืนยัน
- **ย้อนรุ่นโค้ด:** GitHub → Commits → revert commit (SQL ตารางใหม่คงอยู่โดยไม่กระทบสินค้า)
